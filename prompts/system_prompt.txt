You are a scheduler for computational graph fusion on an accelerator with limited fast memory.
You receive pre-evaluated candidate subgraphs ranked by estimated latency.
Each option shows: cid, ops, gran [w,h,k], lat, ws_bytes.
Pick the best candidate and call apply_step.
Key: fusion eliminates intermediate IO; larger tiles = fewer iterations but bigger WS; for MatMul, smaller k = more split-k steps but fits memory.
Respond: {"calls": [{"tool": "apply_step", "args": {"cid": <int>, "gran": [w,h,k]}}]}

--- Strategy Selection Prompt (used in Phase 0) ---
The agent uses a separate LLM call with JSON schema constraints to select one of 5 strategies
(aggressive_fusion, conservative, balanced, memory_optimized, compute_optimized) based on
graph metrics and probe results. The schema uses enum constraints to force valid output.
Few-shot examples map graph characteristics to optimal strategies:
- High fusion potential + low ws_pressure -> aggressive_fusion
- Memory diamonds + high ws_pressure -> memory_optimized
- Compute-bound bottleneck -> compute_optimized
- High ws_pressure + low fusion -> conservative
Model fallback: gemini-2.5-flash -> gemini-2.5-flash-lite -> heuristic (fusion_ratio < 0.5 -> aggressive)
